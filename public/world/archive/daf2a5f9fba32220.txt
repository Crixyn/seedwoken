## Mobile and tablet equivalents

No essential behavior should depend on hovering.

Desktop responses should translate into:

-  Press compression rather than hover lift 
-  Short biological pulses from the touch point 
-  Persistent selected states 
-  Swipeable lifecycle/reference areas 
-  Clear tap confirmation 
-  Larger touch targets 
-  No cursor-following effect on touch devices 
-  No delayed actions that make taps feel sluggish 

Pointer capabilities should be detected through input features such as hover and fine-pointer support, not screen width alone.

## Premium button behavior

The current buttons can support a shared premium button system without changing their underlying actions.

The safe sequence is:

1.  Immediate press compression 
2.  Very short internal biological light/pigment response 
3.  Action execution 
4.  Loading or success state where saving occurs 
5.  Return to rest without layout movement 

Effects should never obscure labels, move the click target, delay destructive choices, or make Canon approval feel playful or ambiguous. Canon decisions should receive restrained, deliberate motion.

## Reduced-motion requirements

The current implementation has no reduced-motion support. Visual v1 should add a global reduced-motion mode that:

-  Replaces video autoplay with its poster frame 
-  Disables cursor-following and parallax 
-  Removes large scaling and traveling effects 
-  Replaces page movement with brief fades or immediate changes 
-  Stops decorative looping animations 
-  Preserves essential loading and success feedback 
-  Maintains visible selected, pressed, and focus states 

## Quiet reading areas

The following should remain low-motion:

-  Biology system rows 
-  Technical explanations 
-  Glossary entries 
-  Canon Update Queue statements 
-  Forms and field labels 
-  Biological-detail mode 
-  Unknown/proposed/canon labels 

Motion should frame the information—not animate the information itself.

## Future 3D specimen compatibility

The current interface does not block future 3D viewing. The sticky specimen panel in Biology is an excellent eventual viewer location, and the Visual Lab provides a natural management surface.

However, two architectural limitations must be addressed before 3D work:

-  The present specimen graphic is a decorative CSS component rather than a replaceable viewer module. 
-  Species data does not yet include structured anatomical regions, parent/child relationships, selectable geometry identifiers, or 3D asset references. 

For Visual v1, the specimen surface should become a self-contained component with clean pointer-event boundaries. That will let a future 3D viewer replace its internal display without rebuilding the Biology workspace.
